## 0. 目的

Phase A で本家追従パイプライン（`upstream-diff.sh`、adapter、tracking 台帳）の信頼性は回復した。v1.1 はこの基盤の上で:

1. **本家追従ギャップを埋める**: v1.13〜v1.20 で本家が追加した `/landing-report` `/gstack-claude` を取り込み、SKILL.md 群を v1.20 ベースに揃える。
2. **既存スキル `/gstack-review` の認識問題を解消する**: フロントマター契約を満たしているのに VS Code Copilot Chat から呼べない問題を直し、再発防止のテスト契約を追加する。
3. **Windows 公式サポートを再開する**: 本家が v1.0 から公式対応している Windows 11（Git Bash / WSL2）を、我々も明示的にサポート OS に戻す。
4. **`copilot-instructions.md` のルーティングテーブルを v1.20 に同期する**。

## 1. 前提（Premises）

レビューで真っ先に挑戦すべき前提を明示する:

| # | 前提 | 根拠 | 弱い場合の影響 |
|---|---|---|---|
| P1 | upstream の `/landing-report` `/gstack-claude` は Copilot CLI / VS Code Chat でも価値がある | upstream は Claude Code 中心の設計。両スキルとも `/ship` の workspace-aware 補助と Outside Voice 拡張で、ホスト依存性は低い | 価値が薄ければ取込工数が無駄 |
| P2 | `/gstack-review` 未認識問題は「フロントマターまたは命名」のいずれかが原因 | 他スキルは認識されている = ファイル配置やビルド系の問題ではない | 環境固有問題なら根本対応にならない |
| P3 | Windows 11 ユーザーは存在し、追跡対象として戻す価値がある | upstream が公式対応、issue ではないがメモで「Linux 統一」が誤りと特定済み | 実ユーザーがいなければ E-1〜E-4 は overkill |
| P4 | v1.1 は単一リリースで出す（Phase B + E を分けない） | Phase A で配管が直り、両者は独立度が高い | テスト時間が膨らむ／ロールバック範囲が広がる |
| P5 | adapt-upstream-skill.sh の「ローカル名 ≠ upstream 名」マッピング機能は B-3 と同時に必要 | `gstack-review` の同期がこの問題でブロックされている | B-3 の自動化が完成しない |

> **CEO Premise Gate**: ユーザー確認はこの 5 件のみ。他は autoplan の 6 原則で自動判定する。

## 3. 実装手順

### B-1: `/landing-report` + `bin/gstack-next-version`

1. `bin/upstream-diff.sh --update` で upstream を最新化
2. `bin/adapt-upstream-skill.sh landing-report` を実行（Phase A で adapter 修正済み）
3. `.github/skills/landing-report/SKILL.md` を生成、フロントマター手動チェック
4. `bin/gstack-next-version` を vendor（bash 実装、`gh pr list` で VERSION 衝突検出）
5. `.github/skills/ship/SKILL.md` の workspace-aware セクションを実コード化（現在は記述のみ）
6. テスト: `gstack-next-version` の単体テスト（`gh` モック）

### B-3: `/gstack-review` 認識問題 + 既存スキル同期 ※ v1.0.3 で先行出荷

**Step 1: 根因特定（調査）**

切り分け対象:
- description 長さ（VS Code/Copilot 側に上限はあるか? upstream Codex は 1024 文字制約）
- `triggers` 配列形式（VS Code Copilot Chat の期待値と一致するか）
- `allowed-tools` の値（`bash`, `view`, `task`, `web_search` 等が GitHub Copilot 側で未知ツールとして弾かれるか）
- 名前 `gstack-review` のビルトイン衝突（`/review` 短縮名は安全か）
- 認識される他スキルとのフロントマター diff 比較

切り分け順:
1. 認識成功している `/ship` `/office-hours` のフロントマターと `/gstack-review` を逐項比較
2. 差分項目を一つずつ実験的に取り除く／合わせる
3. 再発防止のため、判明した制約を `test/skill-contracts.test.js` に契約テストとして表現

**Step 2: adapter のローカル名マッピング**

`bin/adapt-upstream-skill.sh` に第二引数として upstream 側スキル名を受け取れるように:

```bash
# 既存: adapt-upstream-skill.sh gstack-review
# 追加: adapt-upstream-skill.sh gstack-review review
```

upstream の `review/SKILL.md` を読み、ローカル `gstack-review/SKILL.md` に書き出すルートを追加。

**Step 3: 既存スキル同期**

`bin/upstream-diff.sh --sync` を実行し、v1.13〜v1.20 で本家が SKILL.md に入れた変更を一括反映。差分は git diff で確認、preamble 削減等の構造変更がローカル特化部分（日本語注記、host 切り替えフォールバック）を壊さないか fence balance テストで検証。

### B-4: `copilot-instructions.md` 追従

1. upstream `CLAUDE.md` v1.20.0.0 を vendor 取得
2. diff を取り、ルーティングテーブル更新（新スキル `/landing-report` `/gstack-claude` を追加、消えたスキルを削除）
3. スキル数表示を整合（現在 38 → 40 想定）
4. Outside Voice ルーティングが B-2 と整合するか確認

### E-1: README Windows セクション

追記項目:
- 必要ソフトウェア: Bun（推奨） or Node.js + tsx、Git Bash または WSL2 Ubuntu
- インストール手順（Git Bash 想定）: `git clone` → `./setup --host copilot-cli`（Plugin From Source 経由を推奨）
- 既知の制約: Bun の Playwright pipe transport bug（`bun#4253`）→ Node.js フォールバック自動発動
- トラブルシュート: PowerShell 直接実行は非推奨（`bin/browse.ps1` のみ動作）

### E-2: `setup` Git Bash 動作確認

1. Windows 11 + Git Bash で `./setup --host copilot-cli` を実行
2. シンボリックリンクが作成されるか確認（Git Bash は Windows シンボリックリンクを作るには Developer Mode 必須 → ジャンクション fallback or コピー fallback の判断）
3. CRLF/LF 改行コード問題がないか確認（`.gitattributes` で `* text=auto eol=lf` 強制）
4. 必要ならば setup スクリプトに Windows 検知 + 警告メッセージ追加

### E-3: hook の `windows` キー再評価

upstream `lifecycle.json` を確認し、`windows.command` フィールドが存在するか調査。VS Code Copilot Chat の hook 仕様に合わせる。必要なら `lifecycle.json` の各 hook に `windows` キーを追加（PowerShell や cmd フォールバック）。

### E-4: `bin/gstack-open-url` vendor

upstream の bash 実装を移植。OS 判定で `start`（Windows）/ `open`（macOS）/ `xdg-open`（Linux）を分岐。`/landing-report` の PR URL オープン用途。
