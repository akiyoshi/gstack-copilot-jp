# gstack-copilot-jp v1.2 — Outside Voice 刷新（Codex CLI 依存撤廃）

**作成日**: 2026-04-29
**前提リリース**: v1.1.1.0
**追跡 upstream**: garrytan/gstack v1.20.0.0
**目標出荷**: v1.2.0.0（B-2 再開 + Outside Voice 刷新を一括）

> **背景**: gstack-copilot-jp は v1.0 から「VS Code Copilot Chat / Copilot CLI のマルチモデル機能で Outside Voice を実装する」という設計判断を採っているが、SKILL.md 群の表記・bash ブロック・エラーメッセージは upstream（Codex CLI 中心）の名残を引きずっている。本リリースで設計判断と実装表面を一致させる。

---

## 0. 目的

`gstack-copilot-jp` の設計上の真実は **「Outside Voice = task tool / runSubagent + 異モデル指定」** だが、現状はこうなっている:

1. `bin/gstack-codex-probe` は既に `GSTACK_OUTSIDE_VOICE=task` を export する **シム** として動作している（`codex` CLI を呼ばない、auth/version は no-op）
2. しかし autoplan/SKILL.md L231 は `if ! command -v codex >/dev/null 2>&1` で **codex バイナリの存在を実チェック** し、不在なら "[codex-unavailable]" にフォールバックする
3. 17 スキルが「Codex」「Codex returned no response」「Install Codex for cross-model coverage」等の表記を 280 箇所以上保持
4. ship/SKILL.md L1493 は **`npm install -g @openai/codex` をユーザーに推奨**（誤誘導）

これにより:

- VS Code Copilot Chat ユーザーには **意味不明な表示** が出る（codex が無くても動くのに「Install Codex」と出る）
- Copilot のマルチモデル機能（Claude / GPT / Gemini を切り替え可能）が **明示されない** ため、ユーザーがマルチモデル価値を享受できない
- adversarial: 設計判断と実装表面の乖離は、新規貢献者が「実は codex 必須なのか?」と誤読するリスク

v1.2 は次を達成する:

1. **言語の刷新**: 17 スキルから `Codex` を削除し `Outside Voice` / 具体モデル名に置換
2. **唯一の codex 実チェック（autoplan L231）を撤去** し、`gstack-codex-probe` シムの 1 行 source 化
3. **誤誘導の削除**: `npm install -g @openai/codex` 等の推奨を削除
4. **契約テストで再混入を防止**: SKILL.md / `.github/copilot-instructions.md` に `codex` 文字列が混入しないことを検証
5. **adapter で自動置換**: `bin/adapt-upstream-skill.sh` に upstream → local 翻案ルール（`codex → Outside Voice`）を追加し、本家追従時に再混入しないようにする
6. **マルチモデル価値の文書化**: README / DESIGN.md に「2 つの voices = 2 つのモデルファミリー」を明示

## 1. 前提（Premises）

レビューで真っ先に挑戦すべき前提を明示する:

| # | 前提 | 根拠 | 弱い場合の影響 |
|---|---|---|---|
| P1 | VS Code Copilot Chat の `runSubagent` / Copilot CLI の task tool は model パラメータで Claude / GPT / Gemini を切り替えられる | 本セッションで `runSubagent({ model: "Model Name (Vendor)" })` が利用可能、`.gstack/model-routing.yaml` が前提として存在 | 切替不可なら voice 多様性が確保できず、刷新の価値が半減 |
| P2 | 既存の `gstack-codex-probe` シム経由で voice 機構は **既に動いている**（codex バイナリは実際には呼ばれていない） | シム実装 L33-35 で `_gstack_codex_auth_probe` は常に `return 0`、L74-77 で `GSTACK_OUTSIDE_VOICE=task` を export | 動いていないなら言語刷新だけでは不十分、機構自体の再実装が要 |
| P3 | upstream（本家 gstack）は今後も Codex CLI 中心の設計を維持する | upstream-tracking.json で `model overlays` `host abstraction` を「追跡対象外」と明記済み | 本家が方向転換すれば adapter ルールの陳腐化リスク |
| P4 | autoplan の "Dual Voices" は Outside Voice の主要消費者であり、ここを直せば下流（plan-*-review, ship 等）も整合する | autoplan は plan-*-review skill files をディスクから読んで実行する設計（Phase 0 Step 3）、autoplan の表記が変われば呼ばれる側も同期される | 下流が独立に同じパターンを持っている場合、個別修正が必要 |
| P5 | v1.2 は単一リリースで出す（Phase C テスト基盤・Phase D Browser-Skills と分離） | Outside Voice 刷新は 17 スキル横断の「言語契約」変更であり、テスト基盤刷新と混ぜると差分が読めなくなる | 混ぜるとレビュー量爆発、ロールバック範囲拡大 |

> **CEO Premise Gate**: ユーザー確認はこの 5 件のみ。他は autoplan の 6 原則で自動判定する。

## 3. 実装手順

### OV-1: autoplan の Codex preflight 撤去

**Step 1**: Phase 0.5 を「Outside Voice preflight」に書き換え

```diff
- ## Phase 0.5: Codex auth + version preflight
+ ## Phase 0.5: Outside Voice preflight
- Before invoking any Codex voice, preflight the CLI: verify auth (multi-signal) and
- warn on known-bad CLI versions. This is infrastructure for all 4 phases below —
+ Outside Voice は Copilot のマルチモデル機能で実装される（task tool / runSubagent
+ + 異なるモデルファミリー指定）。preflight として、`gstack-codex-probe` シムを
+ source して `GSTACK_OUTSIDE_VOICE` / `GSTACK_OUTSIDE_MODEL` を環境に注入する。
```

**Step 2**: bash ブロックの簡素化

```bash
# 旧（codex バイナリ実チェック）
if ! command -v codex >/dev/null 2>&1; then
  _gstack_codex_log_event "codex_cli_missing"
  echo "[codex-unavailable: binary not found] — proceeding with Claude subagent only"
elif ! _gstack_codex_auth_probe >/dev/null; then
  ...

# 新（シム source のみ）
source .github/skills/bin/gstack-codex-probe
_gstack_codex_log_event "outside_voice_initialized" "model=$GSTACK_OUTSIDE_MODEL"
```

**Step 3**: Phase 1-3.5 の voice セクション書き換え

各フェーズの `**Codex {role} voice** (via Bash)` ブロックを次の形式へ:

```markdown
**Outside Voice ({role}) — via task tool with model override**

primary とは異なるモデルファミリーで subagent を起動する。

```
runSubagent({
  agentName: "{role-specific-agent}",   # design-critic / architect / dx-tester 等
  model: "$GSTACK_OUTSIDE_MODEL",       # gstack-codex-probe が決定
  prompt: "<role-specific challenge prompt>"
})
```

タイムアウト・エラー処理: 同じく degradation matrix を維持する（外側ゲート 12 分）。
コードブロックは task tool / runSubagent インターフェースを表現するもので、
shell コマンドではないことに注意。
```

**Step 4**: ラベル統一

- `CODEX SAYS (CEO — strategy challenge)` → `OUTSIDE VOICE (CEO — strategy challenge)`
- `[codex-only]` / `[subagent-only]` → `[outside-only]` / `[primary-only]`
- `Codex: [N concerns]. Claude subagent: [N issues].` → `Outside Voice: [N concerns]. Primary subagent: [N issues].`
- CONSENSUS TABLE 列ヘッダー `Codex` → `OutVoice`

### OV-2 〜 OV-5: 下流スキルの一括刷新

`bin/decodex-skills.sh`（**新規**、wrapper スクリプト）を作成して機械的に置換:

```bash
# 入力: SKILL.md パス
# 動作:
#   1. CODEX SAYS → OUTSIDE VOICE SAYS
#   2. Codex returned no response → Outside Voice unavailable
#   3. Codex timed out after N minutes → Outside Voice timed out after N minutes
#   4. Install Codex for cross-model coverage → (削除)
#   5. npm install -g @openai/codex → (削除)
#   6. CODEX SAYS [block]: → OUTSIDE VOICE SAYS [block]:
# 出力: 上書き保存（dry-run モードあり）
# 例外: pair-agent.SKILL.md / retro.SKILL.md は allowlist で保護
```

実行順:
1. `--dry-run` で全スキル走査、差分目視
2. 1 スキルずつ適用 → spot check（フェンス balance / 意味の通る英語/日本語）
3. 全スキル完了後 vitest 全グリーン確認

### OV-6: `gstack-codex-probe` の rename 検討

選択肢:
- **A**: rename + symlink 残置（unix/macOS は OK、Windows は要 Developer Mode）

v1.2 で達成しないこと（v1.3+）:
- voice 選択の動的最適化（タスク種別 × コスト × プレミアムリクエスト残量）
- voice の評価指標（disagreement rate, taste decision rate）
- pair-agent の刷新
